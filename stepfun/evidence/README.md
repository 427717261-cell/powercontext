# 验收证据

`e2e-flow.mjs` 每次运行落一份 JSON，记录逐项 PASS/FAIL、当时的模型信息、导入指标与检索结果。
失败的那几份也留着，方便看出问题是怎么被定位和修掉的。

| 文件 | 后端/精度 | 时间 | 结果 | 说明 |
|---|---|---|---|---|
| `e2e-1793159634904.json` | WASM / q8 | 2026-10-28 11:53 | 7/8 | 当时把"刷新前不可见"当成硬断言，用混合检索去验证，必然失败。这是**脚本的断言错了**，不是产品缺陷，已改为按检索路径分别验证 |
| `e2e-1793160734873.json` | WebGPU / fp16 | 2026-10-28 12:12 | 8/9 | "待刷新"断言失败：固定 profile 后 `localStorage` 残留上次选择，用 click 切换开关不幂等。已改为显式置为关闭 |
| `e2e-1793160760381.json` | **WebGPU / fp16** | 2026-10-28 12:12 | **9/9 全绿** | 权威证据（主路径） |
| `e2e-1793160778010.json` | **WASM / q8** | 2026-10-28 12:12 | **9/9 全绿** | 权威证据（降级路径） |

两次全绿运行的模型加载耗时分别是 2040 ms（WebGPU fp16，45.72 MiB）与 1652 ms（WASM q8，23.32 MiB），
均来自本地 `models/` 托管，未走外网。

## 复跑

```bash
npm start                                  # 后端 + 生产前端（8787）
node scripts/e2e-flow.mjs --backend webgpu --port 9384
node scripts/e2e-flow.mjs --backend wasm   --port 9385
```

`--headless` 可强制无头，但 WASM 首次编译 24 MB 模型会明显变慢（实测可达数分钟），
默认走 headful 更快，也便于人工观察。

## 另两份探测数据（非 e2e，用于确认 seekdb 行为）

`probe-visibility.mjs` 与 `probe-latency.mjs` 直接连 seekdb，绕开浏览器，用来定三条检索路径的
索引可见性差异与延迟量级。结论写在 `TECH.md` §3 第 4 条：
向量异步索引可见延迟 145–258 ms（均值 184 ms），全文索引实时，`refresh` 同步生效。
